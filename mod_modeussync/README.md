# Задания из Modeus (`mod_modeussync`)

Activity-плагин предоставляет преподавателю ручной этап создания оцениваемых элементов по заданиям, уже полученным `tool_modeussync` от SyncService.

## Установка и зависимость

Плагин требует установленный `tool_modeussync` совместимой версии. Он использует очередь, настройки подключения (`syncservice_base_url`, `internal_api_key`) и публичный клиент `tool_modeussync\service\SyncService`; контракты SyncService не изменяются.

`tool_modeussync` и `mod_modeussync` необходимо развёртывать из одного релиза. После замены файлов запустите обновление Moodle и очистите кеши; при использовании PHP OPcache также перезапустите PHP-процессы. Это исключает загрузку нового интерфейса `mod_modeussync` со старой моделью очереди `tool_modeussync`.

На курсе может существовать ровно один экземпляр `mod_modeussync`. Он создаётся системой только при наличии заданий в очереди. Добавление и удаление через стандартный интерфейс Moodle запрещены; отсутствующий экземпляр восстанавливает фоновая задача.

## Работа преподавателя

1. Откройте «Задания из Modeus» на странице курса.
2. Для каждой строки выберите тип: «Задание» (`assign`, выбран по умолчанию), «Тест» (`quiz`) или «Семинар» (`workshop`).
3. При необходимости введите переопределение названия. Пустое или состоящее только из пробелов поле оставляет название из Modeus.
4. Нажмите «Создать».

Название из Modeus, `course_modules.idnumber` и максимальная оценка каждого созданного элемента берутся из `courseData`. Непустое переопределение используется как имя элемента; исходное имя в очереди сохраняется. Изменение переопределения у созданного элемента переименовывает его без изменения остальных настроек и без повторной отправки связи. Moodle хранит максимум `assign` как целое число, поэтому дробное значение для выбранного `assign` отклоняется без округления; его можно создать как `quiz` или `workshop`, которые поддерживают дробной максимум. `quiz` создаётся пустым, с одной попыткой и методом итоговой оценки «Лучшая оценка»; вопросы преподаватель добавляет самостоятельно.

Изменение типа созданного элемента требует подтверждения: Moodle показывает список элементов, которые будут удалены и созданы заново. После пересоздания курс повторно отправляется в `/sync`. Если хотя бы по одному выбранному для пересоздания элементу имеется итоговая оценка, подтверждение недоступно; сервер повторяет эту проверку непосредственно перед удалением.

`workshop` — стандартный элемент Moodle «Семинар». Он создаётся в фазе настройки без работ и формы оценивания. Максимальная оценка из Modeus используется как оценка за представленную работу, а оценка за оценивание работ устанавливается в `0`. После создания преподавателю необходимо открыть семинар, настроить инструкции и форму оценивания, а затем переключать его фазы в соответствии с учебным процессом.

При частичной ошибке уже созданные элементы сохраняются, а повторная попытка обрабатывает только отсутствующие. `POST /sync` вызывается автоматически только после создания или обнаружения всех элементов. Если ошибка произошла только при `/sync`, повторная попытка не создаёт элементы заново и повторяет только отправку неизменной связки `id_modeus`/`id_lms`.

Кнопка «Повторить связь» доступна, когда существует хотя бы один уже созданный элемент. Она вручную повторяет только `POST /sync`, не создавая и не пересоздавая задания. Для частично созданной очереди её состояние `pending` сохраняется.

Созданные `assign`, `quiz` и `workshop` затем передаются через штатную задачу `tool_modeussync\task\push_courses`; технический `modeussync` не экспортируется.

## Глобальная повторная синхронизация

Администратору доступна страница «Повторная синхронизация заданий» в разделе плагинов модулей активности. На странице выбирается одна категория курсов. Флаг «Применить к подкатегориям» добавляет к области все дочерние категории рекурсивно; без него обрабатывается только выбранная категория.

После отправки формы создаётся одна фоновая adhoc-задача. В исходную выборку входят только курсы с существующим элементом `mod_modeussync` и очередью заданий. Для каждого такого курса отдельно вызывается существующая операция повторного `POST /sync`. Курсы без реально созданных заданий пропускаются, а ошибка одного курса не останавливает обработку остальных.

Уведомление на административной странице подтверждает постановку задачи в очередь, а не завершение синхронизации. Итоговые количества успешных, ошибочных и пропущенных курсов записываются в журнал выполнения adhoc-задачи.

## Права

- `mod/modeussync:view` — просмотр очереди;
- `mod/modeussync:manage` — выбор типов, создание элементов и повторная отправка;
- `mod/modeussync:addinstance` — служебная capability без стандартных назначений ролям; сама по себе не разрешает ручное добавление.
