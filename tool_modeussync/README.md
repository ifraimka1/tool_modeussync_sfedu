## Плагин для интеграции Modeus с Moodle.

### Фоновые задачи

Фоновых задач (анг. job) четыре:

- pull_courses (создание курсов Moodle по РМУП Modeus)
- push_courses (передача курсов в Modeus)
- pull_members (зачисление пользователей на курсы Moodle по составу команд РМУП Modeus)
- push_grades (передача оценок в Modeus для проставления в Успеваемость)

Задачи по-умолчанию запускаются каждые 5 минут (можно изменить в настройках).

### Особенности работы задач

#### pull_courses

- В запросах SyncService `/new-course` и `/sync` поле `id_lms` содержит строковое `course.idnumber` (ID РМУП). В ответе `/new-course` ожидается то же значение: плагин находит по нему курс Moodle и сохраняет его внутренний числовой `course.id` в очереди заданий. Отсутствующий или неоднозначный `idnumber` приводит к ошибке обработки ответа.

- Для курсов, созданных по данным РМУПа, идентификатор РМУП извлекается из описания вида `Курс создан по РМУП [valid-modeus-id]` и записывается в `course.idnumber`. Перед созданием плагин ищет курсы как по этому `idnumber`, так и по идентификатору РМУП в `summary`, чтобы распознавать ранее созданные курсы со старым `idnumber`. Среди курсов с подтверждённым идентификатором в `summary` сохраняется самый старый по `timecreated`, затем по `id`; остальные удаляются через Moodle API `delete_course()`, включая связанные модули и данные очереди `tool_modeussync`. Поиск по `idnumber` используется как резервный вариант, если совпадений в `summary` нет; одного совпадения `idnumber` без маркера РМУП в `summary` недостаточно для автоматического удаления.
- Целевой курс штатной операции Moodle «Копировать курс» не удаляется как дубль во время backup/restore. После завершения копирования наследованный маркер `Курс создан по РМУП [...]` удаляется из описания копии, поэтому копия остаётся самостоятельным курсом и не участвует в последующей очистке дублей.
- Ошибка удаления дубля блокирует отправку в SyncService только для соответствующего идентификатора РМУП. Остальные успешно обработанные курсы отправляются в `/new-course`, но sync-сессия остаётся незакрытой для повторной попытки проблемного курса.
- Курс без идентификатора РМУП в ожидаемом формате описания не создаётся, поскольку плагин не может обеспечить защиту от дубликатов.
- В Moodle у курсов есть уникальное "короткое имя" или "shortname". Для курсов, созданных по данным РМУПа (опция "Создать курс"), оно формируется из полного названия курса. Если такое короткое имя уже занято, к нему добавляется или в нём увеличивается числовой суффикс (` 2`, ` 3` и далее); при необходимости основа сокращается, чтобы уложиться в ограничение Moodle. С точки зрения синхронизации короткое имя не используется и может быть изменено.
- После отправки созданных курсов SyncService возвращает задания в `results[*].courseData`. Задача сохраняет их в устойчивой очереди `tool_modeussync`, но не создаёт `assign` или `quiz` и не вызывает `POST /sync`.
- Ошибка отправки созданных курсов в SyncService через `/new-course` или обработки его ответа не отменяет успешное создание курсов и не препятствует закрытию сессии `PULL_COURSES`. Ошибка логируется. Если ошибка возникла во время обработки многоэлементного ответа, очереди из уже обработанных элементов ответа могут быть сохранены, а оставшиеся данные поступят только при следующей успешной отправке.
- Очередь хранит исходное имя Modeus и отдельное необязательное переопределение имени, введённое преподавателем в `mod_modeussync`; это значение сохраняется между повторными попытками создания.
- Для ручного подтверждения заданий преподавателем должен быть установлен activity-плагин `mod_modeussync`. При наличии очереди он автоматически добавляет на курс единственный системный элемент «Задания из Modeus».
- Ошибка создания одного курса откатывает только этот курс и не останавливает обработку остальных. Успешные курсы отправляются в SyncService, но вся сессия остаётся незакрытой для безопасного повторного запуска.

#### pull_members

- Плагин отчисляет с курсов пользователей, не найденных в связанном РМУПе. Отчисление можно отключить отдельно для студентов и преподавателей в настройках плагина (параметры `unenrol_students` и `unenrol_teachers`)
- При нескольких Moodle-пользователях с одним внешним идентификатором настройка `allow_person_user_duplicates` определяет, можно ли использовать пользователя с минимальным `userid`. При запрете дублей персона считается отсутствующей.
- Отсутствующие студенты и преподаватели агрегируются по курсам и отправляются в LmsAdapter через endpoint `sync/members/missing`; такая сессия не закрывается как успешная.
- Пользователи с несколькими ролями в контексте курса автоматически не отчисляются.

#### push_courses

- Для отбора курсов для отправки в Modeus плагин использует ограничение по их "возрасту". По умолчанию плагин отправляет курсы не старше 1 года (более старые считаются нерелевантными). Ограничение можно изменить в настройках плагина (параметр `courses_max_interval_minutes`).
- Для мониторинга изменений в модулях курсов используется данные из стандартного журнала событий Moodle, соответственно, он должен быть включен (Администрирование — Плагины — Стандартный журнал событий).
- Созданные преподавателем `assign`, `quiz` и `workshop` экспортируются обычным способом вместе с `cmid`, `idnumber`, названием и фактическим типом. Технический элемент `modeussync` в экспорт не включается.

#### push_grades

- Для отбора оценок для отправки в Modeus плагин использует ограничение по их "возрасту". По умолчанию отправляются оценки не старше 4 недель. Ограничение можно изменить в настройках плагина (параметр `grades_max_interval_minutes`)
- Синхронизируются модульные, курсовые, категорийные и ручные элементы журнала оценок. Для немодульных элементов используется стабильный идентификатор `grade_item_<id>`.
